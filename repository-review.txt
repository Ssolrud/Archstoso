1. EXECUTIVE SUMMARY
================================================================================

ArchTitus and ML4W Dotfiles are fundamentally different projects serving
distinct purposes in the Arch Linux ecosystem:

ARCHTITUS: A bare-metal automated Arch Linux installer that handles disk
partitioning, base system installation, bootloader setup, and optional
desktop environment deployment. It's designed to run from a live ISO and
install a complete Arch system from scratch.

ML4W DOTFILES: A sophisticated, feature-rich Hyprland configuration and
dotfiles package designed to be installed ON TOP of an existing Arch-based
distribution. It transforms an existing system into a polished Hyprland
desktop environment with advanced theming, automation, and customization.

KEY DISTINCTION: ArchTitus INSTALLS the OS. ML4W CONFIGURES the desktop.

2.3 INSTALLATION PROCESS & WORKFLOW
------------------------------------------------------------

Phase 0: Startup (startup.sh)
- Runs system checks (root, Arch ISO, pacman availability)
- Interactive TUI menu system for user configuration:
  * Username & password
  * Hostname
  * Desktop Environment selection (KDE, GNOME, Hyprland, Awesome, etc.)
  * AUR helper choice (yay, paru, picaur, aura, trizen, pacaur, none)
  * Installation type (FULL vs MINIMAL)
  * Disk selection with warning dialog
  * Filesystem type (btrfs, ext4, luks)
  * SSD optimization options
  * Timezone detection (via ipapi.co)
  * Keyboard layout selection
- Saves all choices to configs/setup.conf

Phase 1: Preinstall (0-preinstall.sh)
- Updates archlinux-keyring
- Configures pacman (parallel downloads)
- Sets up country-specific mirrors using reflector
- Disk partitioning with sgdisk:
  * Partition 1: 1M BIOS boot partition (ef02)
  * Partition 2: 300M EFI boot partition (ef00)
  * Partition 3: Remaining space for root (8300)
- Filesystem creation based on user choice:
  * btrfs: Creates subvolumes (@, @home, @var, @tmp, @.snapshots)
  * ext4: Standard ext4 filesystem
  * luks: Encrypted btrfs with LUKS container
- Mounts filesystem hierarchy
- Pacstraps base system (base, base-devel, linux, linux-firmware)
- Generates fstab
- GRUB installation for BIOS systems
- Creates swap file for systems <8GB RAM

Phase 2: Setup (1-setup.sh) - Runs in chroot
- Enables NetworkManager
- Optimizes makepkg.conf for multi-core compilation
- Sets locale to en_US.UTF-8
- Configures timezone and keymap
- Enables sudo for wheel group (NOPASSWD during install)
- Enables multilib repository
- Installs base packages from pacman-pkgs.txt:
  * Respects MINIMAL/FULL installation type
  * Stops at "--END OF MINIMAL INSTALL--" marker for minimal
- CPU microcode detection and installation (Intel/AMD)
- GPU driver detection and installation:
  * NVIDIA: nvidia package + nvidia-xconfig
  * AMD: xf86-video-amdgpu
  * Intel: Full VA-API and Vulkan stack
- Creates user account and adds to wheel & libvirt groups
- Configures LUKS hooks in mkinitcpio if encrypted

Phase 3: User (2-user.sh) - Runs as target user
- Sets up zsh configuration from ChrisTitusTech/zsh repo
- Installs powerlevel10k theme
- Installs desktop environment packages from pkg-files/{DE}.txt
- Installs AUR helper (if selected)
- Installs AUR packages from aur-pkgs.txt
- Applies KDE theming if FULL install selected:
  * Uses Konsave to apply pre-packaged theme
  * Nordic theme integration

Phase 4: Post-Setup (3-post-setup.sh) - Runs in chroot as root
- Installs GRUB bootloader for UEFI systems
- Configures GRUB:
  * Adds cryptdevice parameter for LUKS
  * Adds splash screen parameter
  * Applies CyberRe GRUB theme
- Enables display manager based on DE:
  * KDE: SDDM with Nordic theme (if FULL)
  * GNOME: GDM
  * Others: LightDM with gtk-greeter
- Enables essential services:
  * cups (printing)
  * ntpd (time sync)
  * NetworkManager
  * bluetooth
  * avahi-daemon
- Configures Snapper for btrfs/luks snapshots
- Installs Plymouth boot splash (arch-glow theme)
- Removes NOPASSWD from sudoers and re-enables password requirement
- Cleans up installation files

2.7 TARGET AUDIENCE
------------------------------------------------------------

Primary Users:
- Newcomers to Arch Linux wanting automated installation
- Users familiar with Linux but not with manual Arch installation
- People wanting a quick, preconfigured Arch setup
- Content creators/streamers needing consistent Arch installs
- Those who want a "guided" Arch experience vs pure manual install

Technical Level: Beginner to Intermediate
- Abstracts away manual partitioning and pacstrap
- Provides sane defaults and visual confirmations
- Requires basic understanding of filesystems and partitioning concepts
- Still requires reading warnings and understanding destructive operations

NOT for:
- Advanced users who want complete control over every detail
- Production servers (although server option exists)
- Users who want to learn the manual Arch installation process
- Systems requiring complex partition layouts or dual-boot

3.3 INSTALLATION PROCESS & WORKFLOW

Installation Method 1: ML4W Dotfiles Installer (Recommended)
- Flatpak application: com.ml4w.dotfiles
- Available on Flathub
- GUI-based installation and configuration
- URL-based installation from GitHub
- Two channels:
  * Stable: hyprland-dotfiles-stable.dotinst
  * Rolling: hyprland-dotfiles.dotinst

Installation Method 2: Manual Script Execution
- Clone repository
- Run setup/setup.sh
- Auto-detects distribution (Arch/Fedora/OpenSuse)
- Executes appropriate setup script

Setup Process (setup-arch.sh):

3.4 MAJOR COMPONENTS & FEATURES

A. Hyprland Configuration System

Modular Configuration Architecture:
- Main hyprland.conf is only 74 lines
- Sources modular configs from conf/ directory
- Each aspect has a base .conf file that sources variations
- Variations stored in subdirectories for easy switching

Example: Animation System
- conf/animation.conf contains: source = ~/.config/hypr/conf/animations/...
- conf/animations/ contains multiple animation profiles:
  * default.conf
  * disabled.conf
  * smooth.conf
  * etc.
- User can switch by changing single line in animation.conf

Configuration Categories:
1. Animation: Multiple animation profiles (smooth, disabled, custom)
2. Decoration: Blur, shadows, rounding variations (gamemode, blur, no-blur)

3.6 CONFIGURATION SYSTEM
------------------------------------------------------------

Configuration Philosophy:
- Modular variations for easy customization
- User settings preserved across updates
- Text-based configs with GUI management tools
- Template system for generating configs
- Version tracking for migration

Settings Storage:
~/.config/ml4w/settings/ contains small files defining user choices:
- terminal.sh: Default terminal (e.g., "kitty")
- browser.sh: Default browser (e.g., "firefox")
- filemanager.sh: Default file manager
- screenshot-*: Screenshot tool configurations
- dock-autohide: Enable dock auto-hide
- dock-border.css: Dock border styling
- hide-fastfetch: Disable fastfetch on terminal open
- Various other behavioral toggles

Variation System:
- Base config files point to variations via source statements
- Example: conf/decoration.conf sources conf/decorations/default.conf
- To change decoration style:
  * Edit conf/decoration.conf to point to different variation
  * Or use Settings app to select visually
- Common variations:
  * animations/: default, smooth, disabled
  * decorations/: default, gamemode, blur, no-blur
  * keybindings/: default, custom
  * layouts/: dwindle, master
  * monitors/: default, multi-monitor configs
  * windowrules/: default, gaming, productivity

Template System (ml4w/tpl/):
- Template files for generating configs
- Used by Settings app to write configurations
- Ensures consistent formatting

Restoration System:
- Defined in hyprland-dotfiles.dotinst "restore" array
- On update, specified files/folders are backed up
- User prompted which settings to restore
- Prevents overwriting customizations

Settings Integration (dotinst "settings" array):
- Defines configurable parameters
- Fields:
  * type: "text" for text input
  * mode: "replacesingleline", "overwritefile"
  * title: Display name
  * file: Target config file
  * search: String to find
  * value: Default value
  * template: Format string ([VALUE] replaced)
- Settings app reads this to generate UI
- Changes written back to config files

Version Tracking:
- ml4w/version.json tracks installed version
- Used for migration scripts
- Changelog displayed on update

================================================================================
5. CAN THEY BE USED TOGETHER?
================================================================================

SHORT ANSWER: Sequentially Yes, Simultaneously No

SEQUENTIAL USE (Recommended):
Step 1: Install OS with ArchTitus
- Use ArchTitus to install base Arch system
- Choose "server" or "minimal" desktop environment
  * Avoids desktop environment conflicts
  * Gets bootloader, disk setup, base system
  * Skip Hyprland option in ArchTitus

Step 2: Install ML4W Dotfiles
- On freshly installed system, run ML4W setup
- ML4W installs packages and configures Hyprland
- Benefits:
  * Automated OS install (ArchTitus strength)
  * Advanced Hyprland config (ML4W strength)
  * Best of both worlds

Caveats:
- ArchTitus zsh config will be overwritten by ML4W
- Some package duplication (harmless)
- ArchTitus theming (GRUB, Plymouth) remains
  * Can coexist with ML4W Hyprland config
  * Different system layers (boot vs desktop)


SIMULTANEOUS USE (Not Recommended):
If ArchTitus Hyprland install + ML4W both applied:

CONFLICTS:
1. Hyprland Configuration
   - ArchTitus: ~/.config/hypr/hyprland.conf (basic)
   - ML4W: ~/.config/hypr/hyprland.conf (modular)
   - Resolution: Last one applied wins (ML4W would overwrite)

2. Waybar
   - ArchTitus: waybar-hyprland package
   - ML4W: waybar package
   - Both installed: pacman conflict or one replaces other
   - Different configs: ML4W overwrites ArchTitus config

3. Notification Daemon
   - ArchTitus: dunst
   - ML4W: swaync
   - Both running: Two notification daemons compete
   - Resolution: Disable one in autostart

4. Wallpaper Daemon
   - ArchTitus: swaybg (via Hyprland config)
   - ML4W: swww or hyprpaper
   - Both configured: Hyprland config determines which runs
   - Resolution: ML4W config takes precedence

5. Lock Screen
   - ArchTitus: swaylock-effects
   - ML4W: hyprlock
   - Different keybindings and configs
   - Resolution: ML4W config overwrites keybindings

6. Display Manager
   - ArchTitus: Enables SDDM service
   - ML4W: Optional SDDM with different theme
   - Service conflict: Only one can be enabled
   - Theme conflict: Different SDDM configs

7. Shell Configuration
   - ArchTitus: ChrisTitusTech zsh config
   - ML4W: ML4W zsh config (or bash/fish)
   - .zshrc conflict: One overwrites the other

8. Terminal Config
   - Both: Use kitty
   - ArchTitus: Includes 200+ kitty themes
   - ML4W: Material-themed kitty
   - Minor conflict: Different configs, ML4W overwrites


COMPATIBILITY LAYERS:
These components from ArchTitus can coexist with ML4W:

Boot Layer (No Conflict):
- GRUB bootloader with CyberRe theme
- Plymouth boot splash (arch-glow)
- Reason: Different system layer, not desktop config

System Services (No Conflict):
- CUPS (printing)
- NetworkManager
- Bluetooth
- NTP
- Reason: System-level services, both use same

Snapshot System (Compatible):
- ArchTitus: snapper (for btrfs)
- ML4W: Optional timeshift
- Can coexist: Different tools, same goal
- Resolution: Use one or both

Packages (Mostly Harmonious):
- Shared packages: Both install, no conflict
- Unique packages: Additive, no conflict
- Replacement packages (waybar): One replaces other
- Gaming/VM packages from ArchTitus: ML4W doesn't touch


MIGRATION PATH (ArchTitus -> ML4W):

If you have ArchTitus Hyprland install and want ML4W:

1. Backup Current Config
   $ cp -r ~/.config/hypr ~/.config/hypr.archtitus.backup

2. Backup ArchTitus Folder
   $ cp -r ~/ArchTitus ~/ArchTitus.backup
   (Note: ArchTitus scripts delete themselves, may not exist)

3. List Current Packages
   $ pacman -Qqe > ~/installed-packages.txt
   (Reference for what ArchTitus installed)

4. Install ML4W
   $ git clone https://github.com/mylinuxforwork/dotfiles.git
   $ cd dotfiles
   $ ./setup/setup.sh

   Or use Dotfiles Installer (Flatpak)

5. ML4W Overwrites
   - ~/.config/hypr/* replaced with ML4W configs
   - ~/.config/waybar/* replaced
   - ~/.config/kitty/* replaced
   - ~/.zshrc replaced (if using zsh)

6. What Remains from ArchTitus
   - GRUB theme (CyberRe) - in /boot partition
   - Plymouth theme (arch-glow) - in /usr/share
   - Enabled system services (CUPS, etc.)
   - Base system packages
   - Gaming packages (Steam, Lutris, etc.)
   - VM packages (QEMU, virt-manager)
   - Additional utilities (htop, etc.)

7. Cleanup (Optional)
   - Remove duplicate packages:
     $ sudo pacman -R dunst swaylock-effects swaybg waybar-hyprland sddm-git
   - Or keep them, harmless if not running

8. Test New Config
   - Reboot or restart Hyprland
   - ML4W config should load
   - Check for errors in Hyprland log:
     $ hyprctl log

9. Restore Desired ArchTitus Elements
   - If you liked ChrisTitus zsh:
     $ cp ~/.zshrc.archtitus.backup ~/.zshrc
   - If you want ArchTitus keybindings:
     Merge into ~/.config/hypr/conf/keybindings/default.conf


USING BOTH SIMULTANEOUSLY (Advanced):

Possible but Complex:
- Requires manual config merging
- Cherry-pick desired components from each
- Maintain custom hybrid configuration

Example Hybrid:
- OS Install: ArchTitus (gets system set up)
- Hyprland Config: ML4W base + custom modifications
- Gaming Packages: ArchTitus list
- Theming: ML4W dynamic theming
- Boot: ArchTitus GRUB + Plymouth
- Snapshots: snapper (ArchTitus) OR timeshift (ML4W)

Maintenance Burden:
- Updates to either project may break hybrid
- Manual resolution of conflicts
- No automated update path
- Only for advanced users comfortable with conflict resolution


RECOMMENDED APPROACH:
Choose one for Hyprland configuration:
- If starting fresh: ArchTitus -> ML4W migration
- If existing Arch: ML4W only
- Don't run both Hyprland configs simultaneously

Combine strengths:
- ArchTitus: OS installation, gaming/VM packages, boot theming
- ML4W: Hyprland desktop environment and theming

This gives:
- Automated Arch installation (saves time)
- Professional Hyprland config (best experience)
- Gaming ready (ArchTitus packages)
- Beautiful boot (ArchTitus GRUB/Plymouth)
- Beautiful desktop (ML4W theming)

✗ Want to learn Arch manually (use Arch Wiki instead)
✗ Prefer different Hyprland dotfiles (JaKooLit, Prasanthrangan, etc.)
✗ Want pure, minimal Hyprland (configure from scratch)
✗ Use Arch-based distro other than pure Arch (e.g., EndeavourOS)
  (May have own installers or conflicts)

MIGRATION PATHS:
------------------------------------------------------------

From ArchTitus Hyprland -> ML4W:
1. Backup ~/.config/hypr
2. Install ML4W Dotfiles
3. ML4W overwrites Hyprland config (expected)
4. GRUB/Plymouth themes remain (different layer)
5. Gaming/VM packages remain (ArchTitus advantage)
6. Enjoy advanced Hyprland config

From ML4W -> Different Hyprland Dotfiles:
1. Backup ~/.config/ml4w (settings)
2. Remove/replace Hyprland configs
3. Install alternative dotfiles
4. Manually reinstall preferred ML4W utilities if desired

From Either -> Vanilla Hyprland:
1. Remove dotfiles configurations
2. Backup first (for reference)
3. Start with clean Hyprland config
4. Build up from minimal base


FINAL THOUGHTS:
------------------------------------------------------------

ArchTitus and ML4W Dotfiles are NOT competitors - they solve
different problems:

ArchTitus: "I need Arch installed"
ML4W: "I need Hyprland configured"

The ideal scenario is using ArchTitus (or archinstall) to get a
working Arch system, then installing ML4W Dotfiles to get a polished
Hyprland desktop.

If choosing only one:
- Installing OS from scratch? ArchTitus (but consider archinstall)
- Already have Arch? ML4W Dotfiles (no question)

If ArchTitus wasn't deprecated, it would be a stronger
recommendation. As it stands, ML4W is the actively maintained,
feature-rich, future-proof choice for Hyprland specifically.

For OS installation, consider the official archinstall as an
alternative to ArchTitus - it's maintained, flexible, and part of
the official Arch ISO.

Both projects represent significant effort and skill. ArchTitus
automated a complex process and helped many users get started with
Arch. ML4W Dotfiles showcases what's possible with dedicated focus
on a single desktop environment.

Choose based on your needs, skills, and where you are in your Linux
journey. Both can teach you something about Arch, automation, and
desktop configuration.
